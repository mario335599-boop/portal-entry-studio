# LINE不動産 Portal Entry Studio Ver.1

**Property Data Reader & Portal Workflow Manager**

販売図面PDF → ブラウザ内解析 → 人間の確認 → 案件保存 → ChatGPT Workへの指示 → 結果取込 → 進捗管理を行う静的Webアプリです。SUUMO / at homeを直接操作する機能はありません。

空のフォルダーから作成した独立プロジェクトです。参考例として提示された他者のWebツール・リポジトリ・デザインは流用していません。汎用のオープンソースライブラリのみ、ライセンスに従って使用しています。

GitHub初心者向けの新規リポジトリ作成手順は [GITHUB_SETUP.md](GITHUB_SETUP.md) を参照してください。公開先はご自身の `portal-entry-studio` リポジトリを想定しています。

公開版: <https://mario335599-boop.github.io/portal-entry-studio/>

ソースコード: <https://github.com/mario335599-boop/portal-entry-studio>

## 起動

Node.js 22.12以降、pnpm 11を使用します。サーバーは開発・配信時のみで、運用に独自バックエンドは不要です。

```sh
npm install -g pnpm@11.19.0
pnpm install --frozen-lockfile
pnpm assets
pnpm dev
```

表示されたローカルURLをChrome / Edge / Firefox等の通常ウィンドウで開いてください。`file://` でHTMLを直接開く方法には対応しません。最新のデスクトップChrome / Edgeを推奨します。

今回の作業環境では依存関係とビルドを準備済みです。ターミナルで `./start-local.sh` を実行すると、通常は `http://127.0.0.1:4173/` で起動します。終了はターミナルで Ctrl+C を押します。

```sh
pnpm test          # パーサー・安全条件・バックアップ検証
pnpm build         # dist/ に自己完結する静的配信ファイルを作成
pnpm preview       # 本番ビルドをローカルで確認
pnpm test:e2e      # 本番ビルドに対するChromeブラウザテスト
```

ブラウザテストは `/usr/bin/google-chrome` を使用します。別の環境では `CHROME_PATH` にChromeの実行パスを設定してください。テストは日本語フォントを使用します。テスト内の物件は架空です。

## GitHub Pagesへの公開

### 推奨: GitHub Actions

1. GitHubで公開先リポジトリを作成します。ソース一式と `pnpm-lock.yaml` を `main` ブランチに配置します。`node_modules/`・利用者のPDF・バックアップJSONはリポジトリに入れないでください。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. `main` へのpush、または **Actions → Deploy Portal Entry Studio to GitHub Pages → Run workflow** で配信します。
4. Actionsに表示されたPages URLを開きます。相対アセットパスを使用しているため `https://USER.github.io/REPOSITORY/` のサブパスでも動作します。

`.github/workflows/pages.yml` は、依存関係インストール → ドメインテスト → ビルド → Pages配信を実施します。PDF/OCRライブラリ、日本語・英語辞書はビルド時に同梱します。通常利用者にNode.jsのインストールは不要です。

### ビルド済みファイルの配置

`dist/` の**中身**をPages配信用ブランチのルートへ配置し、Pagesでそのブランチを指定する方法も使えます。`index.html` と `assets/` と `vendor/` をまとめて配置してください。`vendor/` は約39MBで、OCRに必要です。

このリポジトリではGitHub Actions方式のPages配信を有効化しています。`main` ブランチへのpush後、テストとビルドに成功した場合のみ公開版が更新されます。HTTPSは強制されています。

## 主な操作

1. **販売図面を登録**、またはドロップ領域でPDFを選択します。複数ファイルを順番に処理し、各PDFを別案件として保存します。
2. 案件名を押すと、原本PDFと項目候補を並べて表示します。ページ移動・拡大縮小・原文表示に対応します。
3. 数字、単位、号棟、住所を原本で照合します。必要に応じて修正し、項目ごとの **この値を確定** を押します。編集すると確定状態と最終確認が解除されます。
4. 未取得項目は不明です。原本にない情報を補完しないでください。交通・接道は複数行を保持できます。住居表示と地番は別項目です。
5. 一覧で案件を選択し、**TEST MODE**（1件）または **BATCH MODE**（複数件）で **Work用指示を生成** します。未確認数を表示してから、確定値だけを出力します。
6. 指示をコピーしChatGPT Workへ貼り付けます。ログインが必要な場合は人間が対応します。
7. **Work結果を取込** に最終報告を貼り付け、案件と更新予定の状態を確認して反映します。指示末尾のID付きJSONが推奨です。通常テキストでは対象案件を手動指定してください。
8. 写真・間取りの登録、要確認事項の処理、最終確認は人間が外部ポータルで行い、進捗を記録します。
9. 外部ポータルで人間が公開した後に、**外部公開の記録 → 公開済み** に変更します。確認ダイアログを経て記録するだけで、外部サイトへ通信しません。

### Work報告のJSON

```json
{
  "results": [
    {
      "id": "生成された指示に記載された案件ID",
      "suumo": "下書き完了",
      "athome": "要確認",
      "notes": "引渡時期について人間の確認が必要"
    }
  ]
}
```

取込が変更できるのはSUUMO / at homeの進捗と人間へのメモのみです。既存メモは保持して追記し、最終確認を未確認に戻します。画像や公開記録をWork報告から自動確定しません。解決したメモは人間が整理してください。

## PDF・OCR・抽出ルール

- [PDF.js](https://mozilla.github.io/pdf.js/) が各ページのテキストレイヤーを優先して読み取ります。位置から行を再構成します。
- 有効文字が20文字未満のページだけ、[Tesseract.js](https://github.com/naptha/tesseract.js) で日本語・英語OCRを行います。画像化されたページと文字ページが混在するPDFにも対応します。
- OCRはWeb Workerで実行します。画像の最大画素数を制限し、進捗・中止操作・タイムアウト・失敗表示を設けています。
- キーワード辞書は `src/fields.js`、抽出規則は `src/parser.js` に分離しています。あいまいな「土地」「建物」だけの表示を面積と決めつけず、未分類原文に保持します。
- 値、抽出時の値、原文、ページ、方法、確認日時を保持します。㎡と坪を換算・置換しません。
- 異なる候補は改行で併記し、要確認にします。複数交通・複数接道も原文をまとめて人間が照合します。
- 自動抽出値を確定にする処理はありません。OCR候補はすべて要確認です。
- 住所の構成要素は資料に明示されたラベルがある場合に抽出します。町名・丁目・番地等の自動推測分割は行わず、手動編集できる別項目として保持します。

## 保存・バックアップ

- 案件、原本PDF、設定はブラウザの **IndexedDB**（`line-portal-entry-studio`）に保存します。サーバーDBはありません。
- 入力変更は順番に保存します。失敗時は未保存表示になり、確認画面の **保存を再試行** から再保存できます。
- **設定・バックアップ → EXPORT BACKUP** で全案件・PDF・確認状態・進捗・URL設定をJSONに書き出します。
- **IMPORT BACKUP** はschemaVersion・全項目・状態・URL・PDF形式・ID重複を検証し、確認後、1つのトランザクションで復元します。同じIDは上書きし、その他の案件を削除しません。不正JSONや容量不足による途中の書換えを防ぎます。
- schemaVersionは現在 `1`。未対応バージョンは安全に拒否します。将来の変換は検証の前段に追加できます。
- 不正な保存案件を起動時に検知した場合、削除せず救出JSONを書き出せます。
- 保存領域はブラウザ・プロファイル・オリジン単位です。端末間の同期はありません。ブラウザデータの削除や故障に備えて定期バックアップしてください。JSONは暗号化されません。
- 公開先URLやドメインが変わる前にバックアップしてください。同一オリジンの別リポジトリでもIndexedDBを共有するため、独立運用には別オリジンまたは別ブラウザプロファイルを使用してください。

## セキュリティ設計

- **PUBLICATION LOCKED** は常時表示し、解除設定はありません。
- 公開・掲載開始・投稿・本登録・公開申請・掲載申請・予約・自動ログイン・ポータルAPI連携の機能はありません。
- OpenAI / Anthropic / Gemini等のAI APIは使用しません。販売図面や抽出テキストを外部へ送信する処理はありません。
- 実行時の通信は、同一サイトからの静的資産取得だけです。Tesseractの辞書とWASM、PDF.jsのCMap・フォントをすべて同梱します。CDN・外部フォント・アクセス解析を使いません。
- CSPは `connect-src 'self'`、`form-action 'none'`、`object-src 'none'`。PDFはキャンバスに描画し、PDF内のリンク・JavaScript・フォームを操作しません。
- 認証情報の入力欄・保存項目はありません。設定URLはHTTPSに限定し、ユーザー名・パスワード・クエリ・フラグメント・認証トークンを疑うパスを拒否します。認証後の動的URLではなく固定入口URLを登録してください。
- 自由入力・貼付報告に利用者が認証情報を書いた場合に完全検出することはできません。認証情報は入力しないでください。
- HTML表示はエスケープします。Work指示では、資料由来文字列をJSONのデータとし、操作指示として扱わないよう明示します。
- Workに送るのは、値があり確定状態の項目だけです。未確認・要確認・不明の項目名は不足情報として列挙しますが、その値・原文・PDF・未確認ファイル名は送りません。

```text

src/
  app.js                     画面・操作・処理の接続
  style.css                  レスポンシブUI
```

## 技術・使用ライブラリ

HTML / CSS / JavaScript（ES modules）、Vite、PDF.js、Tesseract.js、tesseract.js-core、jpn/eng traineddata、IndexedDB。テストはNode.js test runner、Playwright、pdf-libを使用します。各ライブラリのライセンスを `dist/vendor/licenses/` に同梱します。バージョンは `package.json` とlockfileで固定しています。

## 現在の制限・今後の改善

- 自動抽出はキーワードベースです。自由レイアウト、ラベルのない値、特殊な表、縦書き、小さい文字、傾き、異体字では見落としや誤読があります。確定前の原本照合が必須です。
- 1PDF = 1案件。複数号棟が1PDFに含まれる場合は先に分割してください。住所の意味解析、交通・道路の詳細な構造化、号棟の自動切り分けは今後の拡張です。
- 有効テキストが一部だけある画像混在ページではOCR判定が不十分な場合があります。未分類原文と原本を確認し、手動入力してください。
- 暗号化・破損PDFには対応できない場合があります。パスワード入力は実装していません。1PDFは50MB・100ページ以内、バックアップ取込は500MB以内です。
- OCRの初回読込には辞書ダウンロード時間が必要です。完全なオフラインPWAではありません。配信サイトへアクセスできる状態で使用してください。
- 容量はブラウザ依存。PDF込みJSONの作成・復元はメモリを使うため大量案件は定期整理してください。同時タブ編集、チーム共有、端末同期は対象外です。
- ポータル側の入力必須項目を網羅したバリデーションはVer.1には含みません。確定値が不足した場合はWorkに停止を指示します。
- 将来はポータル項目マッピング、数値監査、詳細な住所・経路・接道モデル、CSV/Excel出力、履歴監査を追加できます。

検証内容と結果は `TEST_REPORT.md` を参照してください。
